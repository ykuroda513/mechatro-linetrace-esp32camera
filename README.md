# mechatro-linetrace-esp32camera

メカトロ実習用のカメラ式ライントレースロボットです。CPUとセンサには **Seeed Studio XIAO ESP32S3 Sense**、モータドライバには **DRV8835（IN/INモード）** を使います。

- 付属カメラで撮った 160×120 のグレースケール画像からラインの位置を求め、PD制御で左右のモータを動かします
- ロボット自身が Wi-Fi アクセスポイントになり、スマホやPCから直接つないで画像の確認、パラメータの調整、START/STOP ができます
- 画像処理と制御の部分は Arduino に依存しないので、PC上でテストできます

## ハードウェア

| 部品 | 備考 |
|---|---|
| XIAO ESP32S3 Sense | カメラは OV2640 または OV3660 |
| DRV8835 モータドライバ（AE-DRV8835-S） | IN/INモード（MODE は D0 から LOW を出力） |
| DCモータ ×2 | 左右独立の二輪駆動 |
| モータ用電源 | VM 2〜11 V。マイコンとは別系統を推奨 |

### 配線

CPU基板とモータドライバ・エンコーダ基板の回路図（2026-10-08版）に合わせています。

| コネクタ | 信号 | XIAO | GPIO | 用途 |
|---|---|---|---|---|
| J3.1 | VCC | 3V3 | – | ロジック電源 3.3V |
| J3.2 | MODE | D0 | 1 | 起動時に LOW を出力して **IN/INモード** にする |
| J3.3 | AIN1 | D1 | 2 | Aチャネル → J5 → M1（**左**） |
| J3.4 | AIN2 | D2 | 3 | 〃 |
| J3.5 | BIN1 | D3 | 4 | Bチャネル → J6 → M2（**右**） |
| J3.6 | BIN2 | D4 | 5 | 〃 |
| J3.7 | GND | GND | – | |
| J3.8 | VM_SENSE | D9 | 8 | ADC。VM を 4.7k/4.7k で 1/2 に分圧したもの |
| J4B.2 | ENC（左） | D5 | 6 | 左車輪のエンコーダ |
| J4A.2 | ENC（右） | D6 | 43 | 右車輪のエンコーダ |

- モータが逆向きに回る場合は、`MOTOR_L_INVERT` / `MOTOR_R_INVERT` を 1 にします
- エンコーダは1相（フォトインタラプタ LBT-131 の出力を 74HC132 で整形したもの）なので、回転方向は検出できません。カウントの符号には、モータへの指令の向きを使っています。立上りと立下りの両方を数えます（`ENC_COUNT_BOTH_EDGES`）
- タイヤ1回転あたりのカウント数（1528）は `ENC_SLITS` と `GEAR_RATIO` から計算しています。Webページには回転数（rpm）も表示されます
- 空いているピン: D7（GPIO44）、D8（GPIO7）、D10（GPIO9）
- スタートボタンには基板上の BOOT ボタン（GPIO0）を、状態表示には基板上のLED（GPIO21）を使います

**注意**

- D6（GPIO43）は UART0 の TX と同じピンです。リセット直後に ROM がこのピンから起動ログを出すため、短い時間ですが 74HC132 の出力とぶつかります。気になる場合は、間に 1kΩ 程度の抵抗を直列に入れるか、右エンコーダを D7/D8/D10 のどれかにつなぎ替えて `PIN_ENC_R` を変更してください
- VM_SENSE で測れるのは、ADCの上限（約3.1V）の2倍、つまり VM がおよそ 6.2V までです。それより高い電源を使うときは分圧比を変更し、`VM_SENSE_RATIO` も合わせてください
- 74HC132 の未使用入力（9, 10, 12, 13）は、GND か VCC に固定してください

### DRV8835 IN/IN モードの駆動方法

| IN1 | IN2 | 動作 |
|---|---|---|
| 0 | 0 | コースト（空転） |
| 1 | PWM(1−d) | 正転・スローディケイ ← **既定** |
| PWM(1−d) | 1 | 逆転・スローディケイ |
| PWM(d) | 0 | 正転・ファストディケイ |
| 1 | 1 | ブレーキ |

スローディケイでは回転速度がデューティにほぼ比例するので、制御しやすくなります。`MOTOR_SLOW_DECAY` を 0 にするとファストディケイに切り替わります。PWMは 20 kHz・10 bit です。

## 開発環境（Arduino IDE）

1. Arduino IDE 2.x をインストールします
2. 「ファイル > 基本設定 > 追加のボードマネージャのURL」に次のURLを追加します  
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
3. ボードマネージャで **esp32 by Espressif Systems**（**v3.x**）をインストールします
4. `firmware/linetrace/linetrace.ino` を開きます
5. 「ツール」メニューで次のように設定します
   - ボード: **XIAO_ESP32S3**
   - PSRAM: **OPI PSRAM**（推奨。「Disabled」のままでも内蔵RAMで動きます）
6. 書き込みます。書き込めない場合は、BOOT ボタンを押したまま USB を挿し直してから試してください

## 使い方

1. 電源を入れると、ロボットが Wi-Fi アクセスポイント **`LineTrace-XXXX`**（パスワード `mechatro`）を立ち上げます。XXXX はロボットごとに決まった値で、シリアルモニタ（115200bps）にも表示されます
2. スマホやPCをこのSSIDに接続し、ブラウザで **http://192.168.4.1/** を開きます
   - スマホが「インターネットに接続されていません」と表示して別の回線に切り替えようとすることがあります。その場合は「このネットワークを使用する」を選ぶか、モバイルデータ通信をオフにしてください
   - 複数台を同じ部屋で使うときは、`config.h` の `WIFI_AP_CHANNEL` を班ごとに 1 / 6 / 11 に分けると混信しにくくなります
   - 既存のアクセスポイントに接続したい場合は、`WIFI_USE_STATION` を 1 にし、`wifi_secrets.example.h` を `wifi_secrets.h` にコピーして SSID とパスワードを書きます
3. 画面のカメラ画像で、次の点を確認します
   - 3本の帯（手前・中間・遠方）に緑のマーカーが出ているか
   - 床が白く、線が黒くはっきり写っているか（写り方は露出とゲインで調整します）
4. **START** を押すか、ロボットの BOOT ボタンを押すと走り出します
5. 調整したパラメータは「NVSに保存」を押すと、電源を切っても残ります。保存していない変更があるときは、保存ボタンの下に「● 未保存の変更があります」と表示されます
   - パラメータの値はすべてロボット側が持っていて、Webページは3秒ごとと再起動時に読み直します。画面の値と実際に使われる値は常に一致します

安全のため、次の場合はモータが自動で止まります。

- 起動直後（STARTを押すまで止まっています）
- ラインを 1.5 秒以上見失ったとき（`LOST_TIMEOUT_MS`）
- 画像の取得に失敗したとき

LEDは、停止中は消灯、走行中は点灯、ラインを見失っている間は点滅します。

### Wi-Fi がつながらないとき

- **アンテナ**: XIAO ESP32S3 は付属の外付けアンテナ（U.FL）を取り付けないと電波がとても弱くなります。必ず取り付けてください
- **対応するネットワーク**: 2.4GHz 帯の WPA2/WPA3-Personal（パスワード方式）に対応しています。eduroam などの WPA2-Enterprise（ID とパスワードで認証する方式）や、5GHz 帯のみのアクセスポイントには接続できません
- **端末どうしの通信**: ゲスト用ネットワークなど、端末どうしの通信を禁止（クライアント分離）しているネットワークでは、PCからロボットにアクセスできません。実習用のルータを用意するのが確実です
- **`.local` が開けない**: mDNS が通らないネットワークや、一部の Android 端末では `.local` の名前が使えません。シリアルモニタに表示される IP アドレスで開いてください
- **カメラの不具合**: カメラが動かない場合もWebページは開けます。ステータス欄に「カメラ初期化失敗」と表示され、LED がゆっくり点滅します

## 調整のコツ

1. **カメラの取り付け**: 手前の帯（画像の下側）に、ロボットの少し前の床が写るようにします。俯角を浅くするほど遠くまで見えますが、近くの解像度は下がります
2. **露出・ゲイン**: 自動露出は切ってあります。白と黒の差（ステータス欄の `C`）が大きく、白が飽和しない値にします
3. **Kp**: Kd=0、基準速度を低めにした状態から Kp を上げていき、ふらつき始める少し手前の値にします
4. **Kd**: 蛇行が止まるまで少しずつ上げます
5. **基準速度**: 少しずつ上げます。カーブで外れるようなら「カーブ減速率」か「先読み」を上げます

## モータテストと速度フィードバック

モータの制御は、カメラの処理とは別のタスク（`drive.cpp`、100Hz）で行います。速度はすべて、車輪の周速（＝前進速度）[mm/s] で表します。

```
ライン位置 → PD (controller.cpp) → 左右の目標速度 [mm/s]
   → drive.cpp (100Hz): エンコーダで実測速度 [mm/s] を計算
        速度FB OFF: duty = 目標 / 最高速度
        速度FB ON : duty = FF×目標/最高速度 + Kp×誤差/最高速度 + ∫Ki×誤差/最高速度   (speed_ctrl.cpp)
   → DRV8835
```

- タイヤ1回転のカウント数は 20スリット × 38.2 × 2エッジ = 1528、タイヤ直径は 58mm です。1カウントあたり π×58/1528 ≒ **0.119mm** 進みます（`config.h` の `WHEEL_DIAMETER_MM`）
- 「最高速度（vmax）」は、duty 100% のときの速度 [mm/s] です。速度FB OFF のときの duty の換算と、速度FB ON のときのフィードフォワードに使います

### 調整の手順

1. **回転方向とエンコーダの確認**：モータテストで、パラメータの「速度FB」を 0（OFF）にして左右とも 200mm/s で回します。両輪が前に回り、`ENC L` / `ENC R` が増えることを確認します。逆に回るときは `MOTOR_L_INVERT` / `MOTOR_R_INVERT` を変えます
2. **最高速度の計測**：「最高速度を測る」を押します。duty 100% で1.5秒回し、後半の平均速度のうち遅い方を「最高速度」に自動で設定します。床に置いて測るのが望ましいです
3. **速度FBの確認**：速度FB を ON にし、200mm/s などでテストします。グラフ（実線＝実測、破線＝目標）を見ながら、`速度FB Kp` / `Ki` を調整します。振動するなら下げ、目標に届くのが遅ければ上げます
4. 最後に、ライン追従の基準速度 [mm/s] と Kp / Kd を調整します

### エンコーダの点検（回転数指定テスト）

モータテストの「回転数」を例えば 10 にして「回す」を押すと、各車輪がエンコーダで10回転分（15280カウント）数えた時点で、その車輪だけ止まります。車輪に印を付けて実際の回転数と比べれば、スリットの欠け・汚れ・ノイズによる数え違いが分かります。左右で回転数が違うときは、まずエンコーダ円板を確認してください。

- エンコーダは ESP32-S3 のハードウェアカウンタ（PCNT）で数え、1 µs 未満のノイズパルスを捨てます（`ENC_USE_PCNT`、`ENC_GLITCH_NS`）
- 「ENCカウント0に」を押してから手で車輪を1回転させると、1528前後になるはずです

## 処理の流れ

```
カメラ 160x120 グレースケール (CAMERA_GRAB_LATEST)
  │
  ├─ line::Detector  (line_detector.cpp)
  │    1. 画像全体で大津の二値化 → しきい値とコントラスト
  │    2. 帯ごとに、列ごとの「線の画素数」を数える
  │    3. 連続する線の列(セグメント)のうち、前回の位置に最も近いものの重心 → pos(-1..1)
  │
  ├─ ctrl::LineController (controller.cpp)
  │    e = (1-look)*手前 + look*遠方
  │    u = Kp*e + Kd*de/dt,   v = base*(1 - slow*|e|)
  │    左 = v+u,  右 = v-u    (速度上限を超えたら左右の差を保ったまま縮める)
  │    見失ったら、最後に見えた側へその場旋回
  │
  └─ Motor (motor.cpp)  DRV8835 IN/IN
```

## ファイル構成

```
firmware/linetrace/
  linetrace.ino      メインループ
  config.h           ピン配置・初期パラメータ ← 最初にここを確認
  camera.cpp/.h      カメラの初期化と露出設定
  line_detector.*    ライン検出（Arduino非依存）
  controller.*       PD制御（Arduino非依存）
  motor.cpp/.h       DRV8835 の駆動（IN/IN、MODEピン制御）
  encoder.cpp/.h     1相エンコーダのカウント（割り込み）
  drive.cpp/.h       モータ駆動タスク（100Hz、速度FB、モータテスト、ログ）
  speed_ctrl.*       速度PI制御（Arduino非依存）
  params.cpp/.h      パラメータ表・NVSへの保存・タスク間の共有
  web.cpp/.h         Wi-Fi（既存APに接続／失敗時はAP）と HTTP サーバ
  wifi_secrets.example.h  接続先 SSID/パスワードのひな形（wifi_secrets.h にコピー）
  web_page.h         調整用ページ（HTML/JS）
tools/
  wifi_ap_test/      Wi-Fi アクセスポイントだけを動かす切り分け用スケッチ
test/
  test_main.cpp      ライン検出と制御のテスト（PC上で実行）
  run_tests.sh       テストのビルドと実行
```

### パラメータの追加

`params.h` の `Params` にメンバを追加し、`params.cpp` の `kParamTable` に1行書き足すと、Webページにスライダーが増えます。`Params` の構造を変えたら、`kNvsVersion` を1つ増やしてください（古い保存データは読み込まれず、初期値で起動します）。

## テスト（PC）

```sh
cd test
./run_tests.sh
```

g++ か clang++ があれば動きます。合成した画像を使って、ラインの位置、線がない場合、白線、分岐、交差点の検出と、PD制御の出力を確認します。

### HTTP API

| パス | 内容 |
|---|---|
| `/` | 調整用ページ |
| `/frame` | 最新の画像 `[w:u16 LE][h:u16 LE][画素 w*h]` |
| `/status` | 検出結果と制御出力（JSON） |
| `/params` | パラメータの一覧（JSON） |
| `/set?kp=1.0&kd=0.05` | パラメータの変更 |
| `/run?on=1` / `/run?on=0` | 走行開始 / 停止 |
| `/save` / `/reset` | NVSへの保存 / 初期値に戻す |
| `/motor?l=200&r=200&ms=2000&fb=1` | モータテスト [mm/s]（fb=1 速度FB / 0 なし。指定時間で自動停止、最大10秒） |
| `/calib` | duty 100% で回して最高速度を測定・設定 |
| `/stop` | すべて停止 |
| `/log` | 直近3秒の目標・実測速度・duty（100Hz） |
